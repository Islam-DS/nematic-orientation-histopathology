# From Equivariance to Nematic Order: Anatomically Supervised Orientation-Tensor Learning in Histopathology

This repository accompanies a manuscript submitted to *Symmetry* (MDPI). It reports a **negative /
inconclusive result**: a D8-equivariant network trained to predict a rank-2 (nematic, Q-tensor)
orientation field, supervised by an independently-constructed anatomical reference, did not meet any of
four prospectively frozen evaluation criteria on the primary dataset, and the negative result was
subsequently found to be robust across five random seeds, a patient-disjoint data partition, five
alternative rotation-consistency metrics, and an external cross-dataset evaluation. This repository
contains the code, frozen configuration, and manuscript source needed to understand and, where dataset
access permits, reproduce that result. **It does not, and does not claim to, demonstrate successful
orientation-tensor learning.**

## 1. Project purpose and scientific question

Glandular orientation in histopathology images is defined only up to a head–tail flip (an axis, not a
vector), which motivates describing it with a symmetric traceless rank-2 tensor — the same mathematical
object used for nematic order in liquid-crystal physics — rather than a plain angle. This project asks
an empirical question: if a neural network's output is *typed* as a rank-2 representation of the
rotation–reflection group D8 (so the correct transformation law under rotation holds by construction),
can that output be trained to reproduce an anatomically meaningful orientation field, judged against a
reference built independently from gland-instance segmentation masks (not from the network's own
input)? The answer found here, under one specific formulation, is no — the reference is not recovered,
and the manuscript reports why that is a scientifically informative result rather than a failure to
hide, along with an exploration of plausible contributing factors that stops short of claiming a
definitive cause.

## 2. Model architecture

The principal model ("Model 3") takes a 3×128×128 RGB image patch and applies two D8-equivariant
convolution blocks (`escnn` `R2Conv`, 5×5 kernels, `InnerBatchNorm`, ReLU, eight regular-representation
fields each), separated by antialiased average pooling. A classification head (group pooling → global
average pooling → linear) predicts the per-patch histologic grade; a Q-tensor head (a 3×3 `R2Conv`
typed to output field `D8.irrep(1,2)`) predicts a dense 2×64×64 map, i.e. a rank-2 tensor `(q₁, q₂)` at
every output location, whose rotation-transformation law `Q' = R(α) Q R(α)ᵀ` holds exactly for the
implemented discrete group by construction. The network has 11,674 parameters. Two predefined baselines
(a non-equivariant plain CNN, and "Model 2," a post-hoc un-typed formulation) and a battery of
ablations, multi-scale reductions, and alternative rotation-metric designs are also implemented; see the
manuscript's Methods section (`manuscript/01_FINAL_MANUSCRIPT.md`) for full detail and
`src/model3_typed_equivariant.py`, `src/model2_posthoc_q.py`, `src/baseline_cnn.py`.

obtain each dataset yourself from its own official source and agree to its own terms before running any

GlaS (the canonical split assignment and de-identified patient IDs used for the patient-disjoint
sensitivity analysis) — metadata generated by this project, not the underlying images.

stage-numbered script is the most direct way to connect a reported number to the code that produced it.

depends on. The Markdown source (`manuscript/01_FINAL_MANUSCRIPT.md`) and the compiled PDF are included
here as the readable record of the manuscript alongside the code that produced its numbers.

## 5. Installation

```bash
conda env create -f environment.yml   # or: pip install -r requirements.txt
```

Requires Python 3.11, PyTorch 2.6.0 (this project used the CUDA 12.4 build on an NVIDIA RTX 3050 6 GB
laptop GPU; a CPU-only or different-CUDA build of PyTorch will also run the code, at greater training
time), and `escnn` 1.0.11 for the equivariant layers. One dependency, `imagecodecs` (used only for
reading the PANDA pilot's TIFF masks), was used by the original project but is not pinned in
`requirements.txt`; install it separately if you intend to reproduce the PANDA compatibility check.

## 6. Reproduction workflow

`src/` has 72 files because the project was built as 28 gated stages, each producing its own script(s);
most of them are not part of the numbers you'd re-run to reproduce the result. **`src/INDEX.md`
categorizes every one of them** — category A (9 files) is the core pipeline below; category B (17 files)
adds the robustness/ablation/cross-dataset extensions; categories C and D (37 files) only render tables,
figures, and manuscript text from results the A/B scripts already computed, and do not need to be run to
reproduce any number.

**You must first obtain GlaS, CRAG, and PANDA yourself** (Section 3) and place them according to the
paths expected by `src/anatomy_targets.py` / `src/stage4_generate_targets.py` (GlaS/anatomical targets),
`src/stage17_crag_targets_and_patches.py` (CRAG), and `src/stage18_panda_compatibility_test.py`
(PANDA). Without the data, the code can be read and audited but not run end-to-end.

With the data in place, the intended order is:

1. `stage4_generate_targets.py` — construct the anatomical reference `Q_anat` from GlaS gland-instance
   masks.
2. `stage10_train_model3.py` — train the primary model (seed 42, frozen configuration).
3. `stage11_geometric_validation.py` / `stage12_rotation_validation.py` — evaluate the four frozen
   criteria (A–D) against `configs/` thresholds.
4. `stage13_permutation_null.py`, `stage14_*` (ablations, multi-scale), `stage15_pathology_analysis.py`,
   `stage16_multiscale_analysis.py`, `stage17_crag_evaluate.py`, `stage18_panda_compatibility_test.py`
   — the secondary/robustness/cross-dataset analyses reported in Results.
5. `stage27_train_and_evaluate.py` (with `--seed`) and `scripts/run_patient_disjoint_multiseed.sh` —
   the five-seed canonical and patient-disjoint multi-seed robustness checks.
6. `stage28_s_distribution_diagnostics.py`, `stage28_gland_patch_size_assessment.py` — the final-stage
   diagnostic analyses.

Each script reads only the frozen outputs of the scripts before it and writes only its own new outputs;
none modifies a prior stage's results. `configs/` contains the frozen evaluation-criteria thresholds
(version 2; see the manuscript's Methods for the calibration history of versions 0–2).

## 7. Evaluation workflow and expected outputs

Running the pipeline above reproduces, on the same data, the numbers reported in the manuscript's
tables: the four primary criteria (Glass's Δ for angular correspondence and tensor similarity, Pearson r
for order-magnitude correlation, per-angle rotation-consistency pass/fail), the ablation and multi-scale
diagnostic tables, the pathology-association tests, the CRAG cross-dataset results, the PANDA
compatibility finding, the five-seed and patient-disjoint multi-seed tables, and the S_DL/S_anat
distribution diagnostics. **Because the primary result is a rigorously negative one, "expected output"
means the same negative pattern reported in the manuscript (criteria not met, effect sizes near zero),
not a positive result** — a re-run that instead met the frozen criteria would itself be a discrepancy
worth investigating, not a sign of a more successful reproduction.

Full-training determinism is not claimed (no deterministic-algorithm setting was enabled); checkpoint
reload was verified bit-identical for the original seed-42 run, but repeat-run numerical
reproducibility beyond that was not separately assessed.
